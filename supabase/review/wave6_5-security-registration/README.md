## Full deletion: authority, stages and exceptions

The new client/Admin route is **disabled** (`NH7_FULL_DELETE_WAVE65_ENABLED` absent). It never falls back to the unproven v252 endpoint, never refreshes/retries into another account and never blanket-clears local caches. Self flow requires exact email + typed DELETE + immutable UID; Admin full-delete is separate from existing Reject/request deletion, owner proof comes from server authority, and target UUID must exist. UI flags are not authorization. Both paths fence async responses against account/token/generation changes. Only verified current self-session may be invalidated; another account's Notes/cache persists. An interrupted request has an unknown result; inspect server job by its immutable request ID before retry, never change its target.

`delete.sql` provides service-only prepare/database/stage functions and deny-all private jobs/scope. Auth-verified actor UUID comes from `edge.mjs` `/auth/v1/user`, not body metadata. Prepare rechecks confirmed actor/target email/current active owner membership, protects active Admin/owner and binds request ID + target UUID + SHA256 email + actor. Current legacy owner fallback needs explicit membership reconciliation at preflight; never substitute a client owner email. The service credential remains server environment only. Target email is transient; jobs retain only UID identifiers, hash, actor/time/aggregate counts, never name/phone/message/raw email.

`delete-orchestrator.mjs` stages: authorize → mandatory proven all-domain write fence → verified owned Storage list/removal (100-object batches, bounded 10000) → database transaction → supported Auth Admin delete → zero-active verification → verified result. Storage remove uses supported API; **never SQL DELETE storage.objects**. Zero-owned-object path works. Underlying retries require provider idempotency and saved server stage. Auth identities/sessions/tokens use supported deletion/cascades; backups/provider/infrastructure logs have independent retention, not active app data.

`edge.mjs` binds supported Auth/Storage transport and RPCs, but **requires approved server-only census/write-fence/listOwned/final-verify ports**. These are deliberate live-schema integration gates, not permission to activate an incomplete adapter. No fallback guesses ownership. The write-fence primitive in delete.sql blocks old-UID JWT writes; every app-domain/definer/service/Storage write path and concurrency behavior must be audited, attached and tested before the worker can be enabled. Ban/revoke refresh alone does not invalidate every existing JWT. Source fixtures prove the port contract; real deployment requires completing those schema-specific adapters from captured live metadata.

Database scope must contain exact approved deployed relation/key/JSON paths in dependency order and indexed identity predicates; an absent/unapproved relation aborts transaction. Strong UID contradictions prevent shared-device/legacy-email collateral deletion. Device ID alone is never a deletion predicate. Email-only rows are removed only while the old target Auth identity still exists; completed-job retries never rescan email and cannot delete a fresh same-email UID. Shared-device-only rows remain quarantined without independent exclusive-owner proof (safe exception; not represented as removed).

Ten source policy exceptions: shared apocrypha catalog, School video catalog/codes (creator attribution requires redaction policy; never purge global content), school_certificates, official_documents_v2 (immutable signed snapshot/public verification), design templates, Library publication versions, Admin audit/membership/grants. Existing issued documents must not be blindly rewritten/deleted. **Active target PII in any exception blocks verified full-delete success** until owner-approved retention/redaction/public-revocation/offboarding policy and schema-specific implementation exists. A minimal non-PII tombstone/security audit may remain. The fixture success case has no active target PII in these exception tables; it separately proves the blocker. Do not describe this as a universally deployable complete live purge.
