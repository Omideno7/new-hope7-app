# Wave 7.5 Admin / Documents — REVIEW ONLY

Nothing here is applied/deployed. No ordinary migration is created. This package reuses the exact immutable Wave5 `candidate.sql` (hash in `baseline-sha256.json`), then adds a narrow companion. The optional Wave5 `library-boundary.sql` is separately hash-bound and included only with `--with-library`; it is **not required for core issuance**. No audio analytics schema/RPC/row/provider is proposed.

Files: `preflight-readonly.sql` (owner metadata capture, not executed), `document-backend-proposal.sql` (server gate, exact retry, atomic delivery, immutable status/history, expire, minimal proof, bounded directory), `rls-acl-proposal.sql` (explicit signatures), `rollback.sql` (disable without deleting), `activation-checklist.md`, `baseline-sha256.json`, `assemble.py` (offline source generation only).

Generate a review artifact outside migrations: `python3 supabase/review/wave7_5-admin-documents/assemble.py --output /tmp/nh7-documents-review.sql`. It refuses changed baseline hashes and overwriting an existing artifact. It concatenates the baseline and companion in **one transaction** so no old full-body verifier/ungated mutation becomes visible between commits. It does not connect to or execute against a database. Optional Library requires separate proven Storage/current Library/RPC contracts and approval; do not add that flag as a workaround.

Authority stays `auth.uid()` plus current exact `private.nh7_admin_is_owner_v350()`. Delegates keep only their existing granted sections; no document permission invented. All table/sequence/private-helper access is denied to clients; authenticated transport RPCs recheck owner and server gate, never cached role/email. The private control defaults **false** and has no client enable RPC. Capabilities require contract75; client flag alone cannot enable writes. Standalone V2 pages keep the existing flag false/absent until separately approved source/config release.

Core model reuses Wave5 drafts/templates/prepared private authoring, immutable official snapshot/number/token/parent, and recipient delivery. Issue locks the draft, binds exact revision/request/prepare token even on retry, calls the original reviewed Wave5 body, then atomically inserts the trusted canonical recipient delivery and one issue event. No email/UID argument is accepted by My Documents; it requires both delivery and official recipient to match current auth.uid(). Manual non-account recipients can receive a PDF directly but have no invented account/archive ownership. New explicit account search is owner-only, capped100 with UUID keyset pagination, no keystroke request/timer; selected recipient is re-resolved by server prepare/issue.

An immutable-row trigger rejects definition/identity/number/token/parent rewrites and deletes. Only current owner/server-enabled revocation or shortened expiry may change status metadata; revocation cannot be reversed. The existing Auth FK's recipient detach is allowed only after that exact Auth UID no longer exists; definitions/history survive. No Full Delete flow is enabled or changed. New private status events are required document audit history, not listening analytics; they do not copy document bodies.

Public V2 verification returns **status + number**, plus the generic `resource=library` marker for optional Library tokens. It never returns a recipient, photo, signature, body, authoring, Admin ID, email, file URL or credential, even to authenticated verification callers. Authorized owner/recipient pages retain the canonical private preview/PDF/Print/Share. Old V2 client full-public output is rejected; no stale body is rendered from a response. QR still encodes only the existing random-token verification URL. Existing legacy certificate routes/data/tokens are untouched.

Storage: default core stores bounded inline images in authorized document JSON and uses existing shipped local assets. It creates **zero Storage buckets, policies, objects or copies**. No private/signed asset URL belongs in a QR or minimal verifier. Optional remote public-asset aliases require exact read-only policy/ownership/provenance review before use; optional Library PDF uploads remain fixed `documents/studio-v2/<current UID>/<version>.pdf`, no upsert, current owner/RPC/hash checks from Wave5 and separate activation. Core issuance is independent of analytics, Library publication, AI and notifications.

Rollback switches the server gate off, hides new-issue entry and revokes exact mutations. Keep the already-proven backend-ready read configuration enabled on verification/My Documents/output pages: the shared ready flag gates reads too, so removing it would unnecessarily hide historical archives/proof. The server mutations=false capability prevents authoring clients from issuing even while that read configuration remains true. It preserves all issued definitions/numbers/tokens/parents, private authoring/templates/drafts, status events and delivery rows, retains minimal verification/current-UID My Documents, and never restores full public disclosure. Existing legacy School certificates and reports are unchanged. No DROP/TRUNCATE/DELETE/history rewrite/cache clearing. Re-enabling after rollback requires the exact reviewed grants/rehearsal and a new explicit approval, not rerunning the older baseline alone.

All live prerequisites and isolated real PostgreSQL concurrency/RLS/rollback checks in the checklist are **BLOCKED_ACTIVATION** until owner evidence exists. PGlite/browser fixtures prove source behavior only. Core source is ready for activation review, not permission to issue a real Production document. There is no unconditional first-real-document approval; after every mandatory prerequisite and later explicit activation/controlled-first-issue approval, the core flow has no dependency on rejected analytics or optional services.
