# Issue #125 — review-only Library production-path hardening

Base: current `main`, `5d376214295491a0d78b2637477a5bbd58eb14e0`. No Production connection, deploy, SQL execution, migrations, grants, data changes, or merge performed. Findings below use the live metadata supplied in Issue #125, rather than claiming another live inspection.

## Root cause and authorization

The live `nh7-content-access` route validates authentication/School approval but selects all active/published `nh7_library_items` using a service-role client. School approval is not a Ministers Library entitlement. A caller can request `action=catalog, resource=library` directly, independently of the correctly filtered UI. The service role cannot be the caller of an `auth.uid()` authorization RPC.

Production already has the appropriate authority: `nh7_library_catalog_v396` filters both items and collections using the current `auth.uid()` grant. Reader v321 (through authorize v230), independent reader v372, and authorize v230/v251 also enforce current entitlement and identity matching. Admin exceptions must come from these server functions, never client role/email/device flags. `nh7-library` is private and its direct Storage policy permits Admin management only. `nh7-library-access` validates `auth.getUser()`, authorizes, then signs for 600 seconds; its deployed implementation is unchanged.

The proposed Edge Library branch calls `/auth/v1/user` with the incoming bearer and then calls catalog v396 with **the same caller bearer and a publishable key**. It never selects a Library table with the service role. Filtering/projection/pagination happens only on the already authorized result set. Scope grants, revocation and Admin handling therefore use the same current server authority as the main client. Unsupported query operators fail explicitly rather than widening the catalog. Other Edge actions and the existing School gate must remain byte-for-byte unchanged when integrating this branch.

## Cache/freshness design — approved Option B

The maintainer explicitly selected [Option B](https://github.com/Omideno7/new-hope7-app/pull/126#issuecomment-6053286033): only Ministers items are online-only. The mixed `nh7-library` bucket is used to recognize Library traffic, **never as the audience classification**. Restricted and unknown items fail closed; public file/reader offline capability is preserved.

Restricted catalog metadata exists only in memory after a successful caller-JWT v396 RPC. It is not written to session/local storage or Cache Storage. Public-only catalog snapshots use `nh7_library_public_v125_<UID>` in session/local storage with UID and verification timestamp. Public snapshots persist across restarts/offline use without the old ten-minute expiry; they contain no grant, token or restricted rows/collections. Every online catalog load still checks v396. A 401/403/`allowed=false` removes that UID's public snapshot and does not fall back to cached content. Offline/transient fallback contains only the matching UID's public snapshot.

Successful, unchanged `nh7-library-access` responses are observed by the Library helper: the returned signed object URL is bound to the requested item ID only if that ID is currently present in a fresh UID-scoped catalog. Public mappings contain exact canonical object identity, item ID, UID, audience and verification time under `nh7_library_public_files_v125_<UID>` and in the Library-only `nh7-library-public-v125` IndexedDB proof store. Signed tokens are not stored as authorization. The binder is private; arbitrary callers cannot register an unknown URL through an exported binding API. Unknown/restricted mappings are never persisted as positive offline authority. The signed-file request payload, server authorization and 600-second signing flow are unchanged.

`NH7OfflineV325.download/status/localPlayable` permits Library reuse only for an exact public identity proof plus the matching UID's verified-public metadata. Online downloads refresh the catalog; permission is checked again before/after web persistence and before native download completion is accepted. Native automatic media substitution uses the same guard. Public web IDB/Cache Storage and native Filesystem operations retain their existing interfaces. The worker serves Library bytes only with an exact public proof; bucket membership alone cannot block public files or authorize Ministers files. Generic legacy reader cache URLs and synthetic stable media deep links cannot bypass the checks. Unrelated audio/School storage and playback paths remain unchanged.

Current public reader responses with `allowed=true` are cached in `nh7reader-public-v125`, keyed by UID/item/language, after a second catalog check. Offline and network-failure fallback is public-only. Non-OK and `allowed=false` responses never replay an old response. Ministers and unknown rows never persist/replay reader text. The maintainer’s [Production-shaped v321 verification](https://github.com/Omideno7/new-hope7-app/pull/126#issuecomment-6065806685) confirms successful v321/v230 bodies have neither `item.id` nor `item_id`. Those legacy email/hash reader bodies remain quarantined, even when their hash/audience/title appears to match a public catalog item. They require one online reopen of the verified PUBLIC item in the requested language to populate the new UID/item/language-scoped cache with a fresh authorized v321 response. No hash-only identity migration is introduced. The existing explicit-response-ID guard remains fail-closed for hypothetical identifiable legacy bodies; the regression no longer claims that real Production bodies satisfy it. Identifiable Ministers reader entries can be deleted; bodies without identity remain quarantined. Fresh catalog reclassification removes public file proofs/bytes and public reader entries; revoked/missing items cannot use a stale public permission. A worker proof identifies public classification, not a minister grant; public bytes carry no privileged entitlement.

Existing public file downloads are not mass-deleted. An online signed-file open binds the exact current public object identity and re-enables safely matching legacy files without re-downloading their bytes. No title/file-name guess or old email/sidecar audience flag is trusted. Unidentifiable legacy copies stay quarantined until verified; identifiable Ministers IDB/cache/native copies are removed when their server-verified object mapping is known. Notes, Bible marks, reader positions, account/School data, and audio downloads are not cleared.

UID/generation guards reject late catalog responses after logout/account switch. Auth/storage events, offline, page restoration, foreground and a one-second watchdog invalidate restricted state; a ten-second heartbeat rechecks while restricted metadata is present, and the restricted snapshot expires after 35 seconds without successful verification. RPCs have a ten-second abort deadline. These are bounded detection, not instantaneous server-push revocation. Public viewers/readers remain usable through a public-only offline transition. Loader versions are `125.4` and the release core cache has an Option B identity so old bucket-wide blockers are replaced.

Limitations: a public item downloaded while genuinely public cannot discover a later server reclassification while offline; its proof/bytes are removed on the next successful online catalog verification. Cached files previously copied outside the app cannot be retracted. Unknown legacy bytes are quarantined by shipped APIs/worker rather than destructively deleting unrelated files; this does not claim to erase arbitrary local forensic copies. Previously issued signed URLs retain the existing 600-second lifetime. Real Safari/iOS/native devices still require approved release testing; native Filesystem behavior below uses a synthetic plugin fixture.
