## Event and language gaps

Registration, prayer, Q&A, assignment and testimony client submission/moderation paths remain their current contracts. No new client polling, submission hook or sensitive text in push will be added. Existing admin_notification_events queue is the convergence point; reviewed triggers must enqueue typed event/source ID/revision, not personal body. Current generic sender is insufficient evidence of closed-app receipt. Current delegates without a category grant must be excluded; no new grants are implicitly assigned.

Actual app preference is `nh7_lang`; directory/registration language can lag. OneSignal language sync currently repeats and is independent of account binding. Preserve documented English fallback for unsupported/unknown preference, make it explicit in server preview, deliver one chosen variant per recipient, and update preference only on an intentional language choice under authenticated identity after the reviewed backend is enabled. Same language/session refresh must not duplicate subscriptions. Push eligible accounts/devices and Inbox eligible accounts must be counted separately, with an explicit shared server-approved-registration audience excluding server-proven Admins.
