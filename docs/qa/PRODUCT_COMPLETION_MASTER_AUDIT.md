## Focused confirmed defects and limits

- New signup stores full DOB in `user.user_metadata.school_registration.birthDate`; current birthday reader reads only top-level metadata and cached email-owned rows. A new account without a matching flattened cache misses its birthday. Cache checks should prefer UID where provided and reject any contradictory UID/email. Use canonical nested metadata read-only, never cache another owner’s name. Session/owner events must close immediately; current `run()` only notices on render/60-second clock. Calendar Tab handling currently traps every Tab on Close even when calendar has focusable event buttons.
- Admin v350 is a real server authority (`auth.uid()` and private memberships/grants, not hardcoded email), but pending bootstrap/sign-in/refresh/load operations are not generation-fenced. Old callbacks can reactivate/restore another session. Existing owner `loadAll` reads bounded registration/student/Q&A first, then many content arrays; current90s refresh is visible-only. Core must reuse these, avoid an independent permission model and suppress stale responses before state application.
- Message Center selected-user mode already maps `{user_id,email,language}` to the deployed source’s selected audience, but no explicit Single mode/segment chooser exists. Audience rerender discards typed variants; selected Map survives across reopen/account unless cleared. Existing direct Send confirmation lacks immutable Preview. Preserve endpoint payload/Edge source unchanged; add draft/preview guards and fail closed when preferred-language copy/recipient identity is incomplete. Source All Inbox is approved-registration based and capped5000, not all Auth users; push/inbox audience equivalence and preferred-language freshness require Wave4 approved contract.
- Storage listing can use authenticated Storage bucket/object list under existing policies. Permission errors must be actionable, not bypassed. Object names without IDs are folders; file listing must be bounded/paged. No unreferenced-file verdict without a reference audit; label candidate only. Existing testimony cleanup is separate and must stay byte-identical.
- Profile has no proven general DOB update contract in current v563/v564 UI; no arbitrary Auth metadata/table write will be added. Document authenticated view/edit requirement for owner review.
- Server-side global search, full request-category aggregate counts, AI campaign draft integration and reliable background Admin request push require explicit contracts; do not invent endpoints or claim delivery. Existing AI status/translation/draft integration remains reachable without automatic sending.
